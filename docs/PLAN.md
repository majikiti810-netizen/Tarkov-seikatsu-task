## 1. 推奨スタック

| 層 | 推奨 | 理由 |
|---|---|---|
| 静的ホスティング（HTTPS） | **Cloudflare Pages** | 無料枠で帯域ほぼ無制限・カスタムドメイン・SSL・Git 連携。PWA に十分。将来 Edge（Workers）で Push 補助も可能 |
| 認証・DB・同期 | **Supabase（Free）** | Postgres + Auth + Realtime + RLS。SQL でタスク／服薬／家計を素直にモデリングできる。無料で API リクエスト無制限寄り。個人 1〜数端末の同期に十分 |
| Web Push | **VAPID + Service Worker**（送信は Supabase Edge Function または軽量 Worker） | 標準 Web Push。iOS はホーム画面追加後のみ。Firebase Cloud Messaging 単体でも可だが、DB を Supabase に寄せるなら送信側だけ Edge Function が単純 |

### 比較メモ（調査時点）

**(a) 静的ホスティング**

| | Cloudflare Pages | GitHub Pages | Netlify |
|---|---|---|---|
| HTTPS / カスタムドメイン | ○ | ○ | ○ |
| 無料帯域 | 静的は実質無制限寄り | ソフト上限 〜100GB/月 | クレジット制（超過に注意） |
| ビルド | 500回/月 | Actions / Pages | クレジット消費 |
| サーバーレス | Pages Functions（Workers） | なし（静的のみ） | Functions あり |
| 向き | **本アプリ推奨** | 公開リポジトリの単純公開 | プレビュー重視 |

**(b) バックエンド（同期・認証・Push）**

| | Supabase | Firebase |
|---|---|---|
| DB | Postgres（リレーショナル向き） | Firestore（ドキュメント） |
| Auth | ○（メール / OAuth / 匿名） | ○ |
| リアルタイム同期 | Realtime | 組み込み同期が強い |
| 無料枠の注意 | 非アクティブ约1週間で一時停止・同時2プロジェクト | Firestore は日次 read/write 上限 |
| Web Push | 自前 VAPID / Edge Function | FCM が強力（ネイティブ向き） |
| 向き | **Web PWA + 複雑な生活データ推奨** | ネイティブアプリ中心なら有利 |

### iOS PWA の重要制約

- **Web Push**: iOS / iPadOS **16.4+**、かつ **ホーム画面に追加した Web アプリとして起動**したときのみ。Safari タブ内では通知 API が使えない場合がある。
- 通知許可はユーザー操作（ボタンタップ）が必須。
- Push 受信時は必ず可視通知を出す（出さないと購読が取り消されることがある）。
- **ストレージ**: iOS はローカルデータの退避（eviction）があり得る。`navigator.storage.persist()` はベストエフォート。**クラウド同期が本命の耐障害策**。
- Android / PC は「インストール」またはブラウザからの通知が比較的素直。

## 2. ユーザー自身が行う必要があること（アカウント作成・ログイン）

エージェントはアカウント作成・デプロイ・ログインを行いません。以下はすべてユーザー作業です。

### フェーズ 0（今すぐ・デモ公開だけ）

1. **GitHub アカウント**でリポジトリを作成し、`demo/` 内容を push  
2. **Cloudflare アカウント**作成 → Pages でそのリポジトリを接続 → 本番 URL（`*.pages.dev`）を取得  
3. （任意）独自ドメインを Cloudflare に接続  
4. iPhone: Safari で HTTPS URL を開く → 共有 → **ホーム画面に追加** → アイコンから起動  
5. Android: Chrome で「ホーム画面に追加」／「アプリをインストール」

### フェーズ 1（同期・ログイン）

6. **Supabase アカウント**作成 → 無料プロジェクト作成  
7. Auth（メールマジックリンクまたは Google OAuth）を有効化  
8. テーブル作成（タスク・買い物・服薬・設定・push_subscriptions 等）と **RLS** 設定  
9. フロントに Supabase URL / anon key を環境変数または設定画面で渡す（公開 anon key 前提、RLS 必須）  
10. 各端末で同じアカウントにログイン → 同期確認  

### フェーズ 2（バックグラウンド通知）

11. VAPID 鍵ペアを生成し、秘密鍵はサーバー側のみに保管  
12. Edge Function（または Cloudflare Worker）で「期限・服薬・習慣」を評価して Web Push 送信  
13. iOS ではホーム画面アプリから通知許可 → 実機でバックグラウンド受信テスト

## 3. いまのアプリ側で準備したこと

- 相対パス・`scope: ./`・SW キャッシュバージョン（`v3-…`）・HTML は network-first  
- iOS 向け meta（`apple-mobile-web-app-*`、`apple-touch-icon`、standalone）  
- **データ層抽象化** `demo/data/adapter.js`  
  - 現行: `LocalStorageAdapter`  
  - 将来: `SyncAdapterStub` → 本番 SyncAdapter（Supabase）に差し替え  
- Push 受信の SW プレースホルダ（`push` / `notificationclick`）  
- 既存機能（任務・会話・買い物・服薬・JSON 入出力）はローカルのまま動作

## 5. 推奨の進め方（短い順）

1. Cloudflare Pages に `demo/` を載せる（#9）  
2. 実機でホーム画面追加・オフライン・SE・服薬を確認  
3. Supabase プロジェクト + 同期アダプタ実装（#25）  
4. Web Push（#15）— 特に iOS はホーム画面から再テスト  
5. 会議レビュー（#10）と習慣系（#18–21, #26）  
6. 健康・振り返り（#12, #17, #27）  
7. 家計・試験・ゲーム（#11, #13, #22–23）  
8. Grok 履歴（#14）は同意とデータ取り扱いを固めてから

## 6. リスクと注意

- 健康・気分機能は**医療診断・治療の代替ではない**。危機時は専門機関へ。  
- 家計明細・会話ログは機微情報。RLS・暗号化・最小権限を徹底。  
- Supabase Free のプロジェクト一時停止に注意（常用する or Pro 検討）。  
- iOS のストレージ退避があるため、「同期なしローカルのみ」は長期運用に向かない。
